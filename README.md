# Автопостинг фото из Яндекс.Диска в VK через RSS

Каждый день в 10:00 по Москве скрипт берёт самое старое фото из папки
`to_post` на Яндекс.Диске, просит нейросеть написать описание по
содержимому фото и добавляет запись в RSS-ленту (`docs/feed.xml`),
опубликованную через GitHub Pages. VK сам периодически проверяет эту
ленту через встроенную функцию **«Импорт RSS»** в настройках сообщества
и публикует новые записи — без ботов-посредников, без токенов VK,
без ограничений по числу постов.

## Почему так

VK в 2026 году не выдаёт самостоятельным приложениям доступ на загрузку
фото в группу (нужна модерация VK). Сторонние боты-посредники либо
платные, либо со строгими бесплатными лимитами. А вот встроенный
«Импорт RSS» — это официальная функция самого VK, не требует
одобрения и полностью бесплатна.

## Что нужно один раз настроить

### 1. Папки на Яндекс.Диске
Создайте на Диске две папки в корне:
- `to_post` — сюда закидываете новые фото
- `posted` — сюда скрипт сам переносит опубликованные

### 2. Токен Яндекс.Диска
1. https://oauth.yandex.ru/client/new → создать приложение, платформа «Веб-сервисы», redirect URI `https://oauth.yandex.ru/verification_code`
2. Права доступа: **Яндекс.Диск REST API**
3. Перейти по `https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID`, разрешить доступ — токен покажется на странице. Это `YANDEX_TOKEN`.

### 3. Ключ OpenRouter
1. https://openrouter.ai → зарегистрироваться по почте
2. Раздел **Keys** → создать ключ — это `OPENROUTER_API_KEY`

### 4. Репозиторий на GitHub и GitHub Pages
1. Создайте репозиторий (можно приватный)
2. Загрузите все файлы из этой папки, сохранив структуру:
   ```
   generate_feed.py
   requirements.txt
   .github/workflows/daily-post.yml
   docs/.gitkeep
   ```
3. **Включите GitHub Pages**: Settings → Pages → Source: **Deploy from a branch**,
   Branch: **main**, папка: **/docs** → Save
4. После сохранения GitHub покажет адрес вида
   `https://ваш-логин.github.io/название-репозитория/` — это и есть `SITE_BASE_URL`
   (без слэша на конце)
5. Settings → Secrets and variables → Actions → добавьте три секрета:
   - `YANDEX_TOKEN`
   - `OPENROUTER_API_KEY`
   - `SITE_BASE_URL` (адрес из шага 4)

**Важно**: если репозиторий приватный, для бесплатного GitHub Pages
может понадобиться сделать репозиторий публичным (Pages на приватных
репозиториях доступен не на всех тарифах GitHub). Если это критично —
можно вынести только папку `docs` в отдельный публичный репозиторий,
а сам скрипт с ключами оставить в приватном.

### 5. Настройка VK
1. Группа VK → Управление сообществом → Настройки → Дополнительно
2. Раздел **RSS** → включите **«Импорт в сообщество»** (у вас уже включено)
3. **Ссылка на файл**: `SITE_BASE_URL/feed.xml` (например
   `https://malkhanow.github.io/vk-autopost/feed.xml`)
4. Сохранить

VK начнёт периодически проверять эту ссылку самостоятельно — частота
проверки определяется самим VK, не настраивается вручную.

## Проверка

1. Закиньте одно фото в `to_post` на Диске
2. В репозитории: **Actions → Daily VK Post → Run workflow**
3. Проверьте, что:
   - в репозитории появился/обновился файл `docs/feed.xml` с новой записью
   - по адресу `SITE_BASE_URL/feed.xml` в браузере видна валидная RSS-лента
   - фото пропало из `to_post` и появилось в `posted`
4. Публикация в VK может занять некоторое время после того, как VK
   в очередной раз проверит ленту — это не мгновенно

## Важные нюансы

- **Скорость появления в VK не гарантирована** — зависит от того, как
  часто VK сам опрашивает RSS-ленту. Обычно это не мгновенно, может
  быть с задержкой в несколько часов.
- **Формат подписи** меняется в `generate_feed.py`, переменная `CAPTION_PROMPT`.
- В ленте хранятся последние 30 записей (`MAX_ITEMS_IN_FEED` в скрипте) —
  можно увеличить.
- Если папка `to_post` пуста, скрипт ничего не делает и завершается
  без ошибки.
