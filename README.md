# SAS — Smart Automation System

Автопостинг по подписке для малого бизнеса. Один движок обслуживает всех
клиентов: у каждого свой конфиг, свои рубрики, свой канал и своя папка на
Яндекс.Диске.

```
Google Форма ──► CRM (Apps Script + Google Таблица) ──► clients/{id}.json
                                                              │
                                            GitHub Actions ───┴──► clients_post.py
                                                                         │
                                                        RouterAI ────────┤
                                                        Яндекс.Диск ─────┤
                                                                         ▼
                                                              Telegram-канал клиента
                                                                         │
                                                              Crosslybot ─┴──► VK + MAX
```

## Что где лежит

| Файл | Что делает |
| --- | --- |
| `clients_post.py` | движок публикации: рубрики, праздники, фото, генерация текста |
| `clients/{id}.json` | конфиг клиента, его собирает и коммитит CRM |
| `clients_state.json` | состояние ротации: какие рубрики и фото уже были |
| `tariffs.json` | реестр тарифов — единственный источник правды |
| `.github/workflows/clients-post.yml` | запуск по слотам и вручную из CRM |
| `crm/` | интерфейс и бэкенд CRM, свой [README](crm/README.md) |
| `tests/` | проверки движка, запускаются без сети |

## Как выходит пост

Скрипт запускается на слот (утро / день / вечер) и для каждого активного
клиента, у которого этот слот выбран:

1. Проверяет, не выпадает ли на сегодня праздник. Праздничный пост
   вытесняет обычную рубрику: за 7 дней и за 1 день — в поздний слот,
   в сам день — в ранний.
2. Иначе берёт рубрику, расписанную на этот день недели. Если рубрик
   несколько, они чередуются по кругу, а не выпадают случайно.
3. Ищет фото: сперва в подпапке рубрики (`{папка клиента}/rubrics/<тема>`),
   иначе в общей очереди `{папка клиента}/to_post`.
4. Просит RouterAI написать текст по промпту рубрики — с учётом
   `style_prompt`, тона и запретов клиента.
5. Публикует в Telegram-канал клиента. Crosslybot кросспостит в VK и MAX.
6. Переносит использованное фото в `posted/`.

Формат подачи выбирается **из набора своей рубрики** (`RUBRIC_FORMATS`), а
не из общего списка, и не отменяет задачу рубрики (`RUBRIC_ANCHOR`). Иначе
в рубрике «Разбор ситуации (FAQ)» выпадало «напиши историю из практики» — и
выходила история вместо разбора вопроса.

Те же наборы продублированы в `crm/Code.gs`: примеры постов, которые CRM
показывает клиенту при настройке, должны писаться по тем же правилам, что и
боевые публикации. Правишь в одном месте — правь и в другом, комментарии в
обоих файлах об этом предупреждают.

## Защита от кривых постов

В канал клиента не должен уходить обрубок. Проверки идут слоями:

- **Обрыв генерации.** Ловится по двум признакам сразу: `finish_reason` от
  провайдера **и** незаконченный хвост текста. Второе обязательно: модель
  регулярно возвращает `finish_reason: stop` с текстом, оборванным на
  полуслове, — именно так в канал ушёл пост, кончавшийся на «Я часто
  замечаю, как меняется настроение человека».
- **Служебные пометки модели** (`Word count check` и подобные) режутся от
  первой такой строки и до конца ответа, а не вырезаются из середины:
  вырезание оставляло висеть недописанное предложение над дыркой.
- **Перегенерация.** Дежурный зачин из стоп-листа, текст короче 40 слов,
  незаконченная мысль, промах мимо жанра рубрики — повод переписать пост.
- **Финальный рубеж.** Тело поста проверяется до приклеивания призыва к
  действию: после него текст всегда заканчивается «правильно», и обрыв
  внутри становится невидимым. Не прошло — пост не публикуется, в CRM
  уходит «Ошибка: неполный текст», фото остаётся в очереди.
- **Выдуманные контакты.** Телефон или ссылка, которых нет в карточке
  клиента, вырезаются вместе с предложением.

`finish_reason` и расход токенов пишутся в лог Actions — следующий сбой
разбирается по логу, а не по скриншоту из канала.

## Отправка в Telegram

`post_to_telegram` устроена так, чтобы пост ушёл при любых проблемах с
картинкой или разметкой:

1. Фото тяжелее `MAX_PHOTO_MB` — отправляется без фото.
2. Ошибка `sendPhoto` — повтор без `parse_mode`.
3. Не помогло — текст уходит отдельным `sendMessage`.

## Праздники

Базовый список — в `BASE_HOLIDAYS`, нишевые клиент задаёт в CRM
(`holidays_extra`). Тариф СТАРТ праздников не получает, как и клиенты,
выбравшие «Не нужны» в брифе. У памятных дат тон сдержанный: ни призыва к
действию, ни хештегов.

Фото берутся из своей библиотеки на Яндекс.Диске —
`{HOLIDAYS_FOLDER}/{ключ}/before/` и `.../day/`. Фотосток убран: по запросу
он выдавал случайные кадры, и в канал клиента уходил мусор.

## Секреты GitHub Actions

| Секрет | Зачем |
| --- | --- |
| `WEBAPP_URL` | адрес Web App CRM — туда пишется статус публикации |
| `WEBAPP_TOKEN` | токен доступа к Web App |
| `ROUTERAI_KEY` | генерация текста, тот же ключ, что в Script Properties |
| `TELEGRAM_BOT_TOKEN` | общий бот, админ во всех каналах клиентов |
| `YANDEX_TOKEN` | OAuth-токен Яндекс.Диска, папки у клиентов разные |

## Папки клиента на Яндекс.Диске

```
{yandex_folder}/
  to_post/            — общая очередь фото
  posted/             — опубликованные
  rubrics/<тема>/     — фото под конкретную рубрику
```

## Запуск

Обычно всё идёт по расписанию. Вручную — **Actions → Clients Post → Run
workflow**: можно указать `client_id` (тестовый пост одному клиенту, день
недели и слот не проверяются) и `slot`. То же самое делает кнопка
«Сохранить и запустить» в CRM.

Публикацию по слотам инициирует триггер `dispatchSlots` в Apps Script —
он ходит каждые 15 минут и запускает workflow вовремя. Расписание cron в
самом workflow оставлено запасным вариантом: оно опаздывает на часы.
Повторную публикацию предотвращает отметка `slot_done` в состоянии.

## Проверки

```
python3 tests/run.py     # движок публикации
node crm/tests/run.js    # бэкенд и интерфейс CRM
```

Сеть, ключи, Google и Яндекс.Диск подменяются заглушками — запускать можно
где угодно, ничего никуда не опубликуется.
